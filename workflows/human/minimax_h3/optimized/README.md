# MiniMax H3 메모리 최적화 워크플로우

ComfyUI의 **Workflows → H3_Optimized_Modes**에서 원하는 JSON을 연다. 목록이 갱신되지 않으면 브라우저를 새로고침하거나 `ComfyUI/user/default/workflows/H3_Optimized_Modes`의 JSON을 직접 불러온다. 기존 워크플로우는 그대로 유지한다.

| 파일 | 입력 / 역할 | 모델과 샘플링 |
|---|---|---|
| `H3_Optimized_T2V.json` | 텍스트만으로 영상과 오디오 생성 | FL2VA, res_multistep, 15+5 / 20스텝 |
| `H3_Optimized_I2V.json` | 시작 이미지를 고정해 영상과 오디오 생성 | FL2VA, 15+5 |
| `H3_Optimized_FirstLast.json` | 시작 이미지와 끝 이미지 모두 지정 | FL2VA, 15+5 |
| `H3_Optimized_V2V.json` | 영상의 구도·동작·소리를 참조해 새 영상 생성 | Singularity REF2VA + R2V용 DMD, Euler 7+1 / 8스텝 |
| `H3_Optimized_AI2V.json` | 이미지와 오디오를 함께 참조해 새 영상 생성 | Singularity REF2VA + DMD, 7+1 |

T2V/I2V/시작·끝 프레임에는 설치된 FL2VA 모델을 사용한다. 설치된 8스텝 LoRA는 REF2VA용이므로 FL2VA에 연결하지 않는다. 이 세 방식도 저해상도 샘플링 → 3D latent x2 확대 → 고해상도 마무리라는 같은 구조를 사용하지만, 8스텝 가속과 동일한 속도를 보장하지 않는다.

기존 R2V는 **Workflows → H3_71_validation**의 검증된 Singularity 7+1을 그대로 사용한다. 새 R2V 복사본은 만들지 않는다. V2V·AI2V는 이 기존 R2V 구성에 해당 참조 입력을 연결한 파생 워크플로우다.

## 공통 메모리 처리

- 참조 입력과 텍스트 인코딩을 마친 뒤 `DenoTextEncoderUnload`로 텍스트 인코더를 해제한다.
- 마지막 고해상도 패스에 `H3MemoryOptimization`을 적용한다. FL2VA 경로에서는 첫 저해상도 패스에도 적용한다.
- 3D latent upscaler에서 temporal chunking을 켠다.
- 두 샘플링 패스가 끝난 후 `VRAM_Debug`에서 전체 모델 언로드, 메모리 캐시 정리, GC를 수행한다.
- 영상·오디오 VAE는 이 언로드 노드의 출력에 연결되어 있어 메모리 정리가 끝난 다음 실행된다.
- H3가 생성한 오디오와 영상을 함께 MP4로 저장한다.

기준 실행 환경은 이 PC에서 성공한 Dynamic VRAM 켜짐, async offload 꺼짐, Python 프로그램의 CUDA 시스템 비대체 선호 설정이다. 워크플로우 JSON 자체는 프로세스 실행 옵션이나 NVIDIA 설정을 변경하지 않는다.

## 실행 방법과 해상도

1. 원하는 워크플로우를 열고 `프롬프트` 노드를 수정한다.
2. 이미지·영상·오디오 로더에 사용할 파일을 지정한다. 참조 이미지 로더는 Upload/Input Folder로 입력 폴더 안의 이미지를 선택한다.
3. `해상도`와 `영상 길이 (초)`를 지정한다.
4. 실행 후 영상과 음성이 끝까지 생성됐는지 확인한다.

기본은 **384×672 → 768×1344**, 요청 길이 **5초**다. 폭과 높이를 바꾸면 **672×384 → 1344×768** 가로 영상이 된다. Manual Input 모드에서는 폭·높이가 실제 크기를 결정하며 `ratio_preset`은 자동 계산에 사용되지 않는다.

768×1344는 정확한 9:16이 아니다. 정확한 9:16 초안은 **288×512 → 576×1024**로 지정한다. 각 변은 32의 배수로 맞춘다. 정확한 1080×1920 납품은 생성 후 비율을 맞춰 리사이즈한다. 해상도·길이를 늘리면 메모리와 생성 시간이 증가한다.

H3의 프레임 수는 24fps에서 `17k+5`에 맞춰 올라간다. 요청 5초는 124프레임/약 5.167초, 7초는 175프레임/약 7.292초, 8초는 192프레임/8초다.

## 입력 방식의 의미

**I2V / 시작·끝:** 입력 프레임은 장면의 시간 위치를 고정하는 조건이다. 시작 이미지는 생성 캔버스에 맞춰 늘리고, 끝 이미지는 비율을 유지하며 cover crop하는 설치된 네이티브 노드 동작을 따른다. 두 이미지를 같은 비율로 준비하면 왜곡과 잘림을 줄일 수 있다.

이 두 방식은 고해상도 패스용 프레임 조건을 최종 x2 크기로 다시 인코딩한다. 저해상도 프레임 조건을 그대로 재사용하면 설치된 H3에서 토큰 크기 불일치가 발생하므로, 첫 패스와 마지막 패스의 conditioning을 따로 연결한다.

**R2V:** 참조 이미지의 인물·스타일을 참고한다. 시작 프레임 자체를 고정하는 I2V와 다르다. 프롬프트에 `<Picture 1>`, `<Picture 2>`처럼 입력 순서에 맞는 태그를 쓴다. 기본 `match`를 유지하고, 큰 참조가 필요한 경우에만 메모리 부담을 고려해 `max`를 선택한다.

**V2V:** 사용자가 요청한 ‘입력 영상을 참조해 새 영상 생성’ 방식이다. `<Video 1>`을 프롬프트에서 참조한다. VHS에서 24fps로 읽고, 입력 영상 높이를 384로 낮추며, 읽는 프레임 수를 요청 길이에 맞춰 제한한다. 소리가 있으면 같은 영상의 `<Audio 1>`도 연결된다. 원본 latent를 denoise strength로 변환하는 방식이나 정확한 카메라·동작 복사를 인증하는 방식은 아니다.

**AI2V:** 사용자가 요청한 ‘오디오+이미지로 영상 생성’ 방식이다. `<Picture 1>`과 `<Audio 1>`을 프롬프트에서 참조한다. 오디오는 기본 0초부터 요청 길이만큼 잘라 참조 입력으로 사용하므로 긴 녹음 전체를 인코딩하지 않는다. `TrimAudioDuration`의 시작 시간을 바꾸면 참조할 구간을 고를 수 있다. 원본 오디오를 최종 MP4에 덮어씌우지 않고 H3가 생성한 오디오를 저장한다. 원본 문장·길이·립싱크가 정확히 재현되는지는 별도 확인해야 한다. 원하는 대사는 프롬프트에도 명시한다.

## 에이전트용 파일

이 폴더의 `H3_Optimized_*.api.json`은 ComfyUI `/prompt`용 실행 그래프다. `.ports.json`은 변경할 입력 위치를 명시한다. UI JSON과 API JSON은 서로 다른 형식이다.

공통 포트: `positive`, `width`, `height`, `duration`, `seed`, `filename_prefix`.

| 방식 | 추가 포트 |
|---|---|
| I2V | `first_frame` |
| 시작·끝 | `first_frame`, `last_frame` |
| V2V | `reference_video` |
| AI2V | `reference_images`, `reference_audio`, `audio_start` |

이미지·영상·오디오 입력 값은 ComfyUI 입력 폴더 기준 이름을 사용한다. `reference_images`는 입력 폴더 기준 이미지 이름을 줄바꿈으로 구분한다. 빈 입력 로더는 사용자가 지정해야 하는 자리이며, 실행 전에 필요한 값을 채워야 한다. API를 패치한 뒤 `/prompt`에 제출하고 해당 `prompt_id`의 `/history`에서 성공 여부와 실제 저장 파일을 확인한다. UI 파일을 API로 오인하거나 에이전트 도구의 가로 전용 프리셋으로 되돌리지 않는다.

## 검증 기록

`validation.json`은 설치된 ComfyUI의 실제 `validate_prompt`로 노드·모델·포트와 UI/API 연결 일치를 검사한 결과다. 빈 입력 자리는 검증 때 존재하는 입력 파일로 채워 검사했다.

`render_validation.json`에는 각 방식의 짧은 실제 생성 테스트 결과가 기록된다. 테스트는 요청 0.9초 → 22프레임, 시작 288×512 → 최종 576×1024다. 이는 전체 실행 경로와 MP4 저장 검증이며, 5~8초 영상의 내용·얼굴·동작·대사·립싱크 품질 검증은 아니다. 테스트 그래프와 결과 경로를 기록해 재현 가능하게 한다.

이전에 원형 Singularity R2V 7+1의 세로 7초·8초 작업은 이 PC에서 전체 저장까지 성공했다. 이번에 추가한 다른 입력 방식의 제작 길이와 품질은 실제 작업별로 검수한다.
